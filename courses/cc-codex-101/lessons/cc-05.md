## 📚 학습 목표 — 4가지 도달 지점

1. **"AI도 업무 매뉴얼이 있어야 한다"** — CLAUDE.md 없이 일 시키던 것과 있을 때의 차이를 눈으로 직접 본다
2. **짧고 명확한 규칙서를 직접 만든다** — 매번 통째로 읽히는 파일이라 꼭 필요한 줄만 남기는 감각을 익힌다
3. **긴 규칙은 따로 빼서 필요할 때 읽게 한다** — 보고서 양식 같은 규칙을 별도 파일로 나누고, 규칙서에는 경로 한 줄만 둔다
4. **이 규칙서가 앞으로 어디에 쓰이는지 안다** — CLAUDE.md가 Codex AGENTS.md · 지식관리 규칙 · 봇 성격으로 자라나는 흐름을 머릿속에 그린다

## 🎯 개념 도입 — CLAUDE.md란 무엇인가

### AI의 기억 문제 — "어제 했던 얘기를 오늘 또 해야 한다"

Claude Code(이하 CC)와 대화할 때마다 지우는 이걸 반복했습니다.

> "저는 1인 사업자고, 뉴스레터를 운영해요. 요약은 3줄 이내로, 말투는 친근하게 해주세요."

어제 말했는데 오늘 또 말해야 합니다. CC는 **세션(대화 한 회)이 끝나면 그 내용을 잊어버리기** 때문입니다. 이건 결함이 아니라 원래 그런 구조입니다.

> **비유 — 기억 초기화 비서**
>
> 아주 능력 있는 비서가 있는데, 출근할 때마다 기억이 초기화됩니다. 그래서 매일 아침 "저는 지우 대표예요. 보고서는 세 줄 요약 먼저, 수치는 반드시 파일에서 인용해 주세요." 처음부터 다시 알려줘야 합니다.
>
> **CLAUDE.md = 비서 책상 위에 올려둔 업무 매뉴얼.** 출근하자마자 자동으로 읽어서 오늘도 어제처럼 일할 수 있게 하는 파일입니다.
>
> 그런데 이 매뉴얼이 백 쪽짜리라면? 비서는 매일 아침 백 쪽을 다 읽어야 하고, 그 사이에 정말 중요한 한 줄을 놓칩니다. **매뉴얼은 짧아야 매일 지켜집니다.**

CC는 새 세션을 시작할 때마다 **CLAUDE.md를 통째로 먼저 읽습니다.** 이 파일에 "나는 이런 사람이고, 이렇게 일해줬으면 해"를 적어두면, 매번 새로 알려줄 필요가 없어집니다. 대신 **적어 둔 모든 줄이 매 대화마다 읽힌다**는 것도 기억해야 합니다.

### CLAUDE.md vs 그냥 말하기 — 어떻게 다른가

```
CLAUDE.md 없을 때                 CLAUDE.md 있을 때
──────────────────────────         ──────────────────────────
매 대화마다 "저는 1인 사업자고…"   파일 한 번 작성 → 이후 자동 적용
말투가 매번 달라짐                 항상 내가 정한 친근한 말투
형식이 제각각                      항상 일관된 구조 (3줄 요약→상세)
실수 방지 장치 없음                금지 사항을 미리 박아둠
```

### 파일 위치에 따라 적용 범위가 다릅니다

| 파일 위치 | 적용 범위 | 언제 쓰나 |
|-----------|-----------|-----------|
| `./CLAUDE.md` (현재 폴더) | 이 폴더에서 CC 켤 때만 | 특정 사업 프로젝트 전용 |
| `~/.claude/CLAUDE.md` (홈 폴더) | 내 컴퓨터 모든 폴더 | 전역 공통 규칙 |
| `./CLAUDE.local.md` | 이 폴더 · 나만 | 팀에 공유 안 할 개인 메모 |

오늘은 **작업 폴더 안에 `CLAUDE.md`를 만드는 것**부터 시작합니다. 가장 빠르게 효과를 느낄 수 있기 때문입니다.

### 좋은 규칙서 세 가지 — 매번 통째로 읽히니까

| 원칙 | 왜 | 어떻게 |
|------|----|--------|
| **① 짧게** | 매 대화마다 통째로 읽혀서, 길수록 읽는 양이 늘고 중요한 규칙이 묻힌다 | 한 파일 200줄 아래. 줄마다 「이 줄을 지우면 AI가 실수할까?」를 묻고, 아니면 지운다 |
| **② 명확하게** | 막연한 말은 AI가 매번 다르게 해석한다. 서로 부딪치는 규칙이 있으면 아무거나 하나를 고를 수 있다 | 「잘 해주세요」 대신 「요약은 세 줄, 숫자는 파일에서 인용」처럼 그대로 실행할 수 있는 문장 |
| **③ 나눠 두기** | 보고서 양식처럼 길고 가끔만 필요한 규칙까지 넣으면 ①이 무너진다 | 그런 규칙은 별도 파일(`rules/보고서-형식.md` 등)로 빼고, 규칙서에는 「보고서를 만들 때는 rules/보고서-형식.md 를 먼저 읽고 따른다」 한 줄만 둔다 → 필요할 때만 열어 읽는다 |

> 📎 **근거 — Claude Code 공식 문서** (https://code.claude.com/docs/en/memory)
> - CLAUDE.md 는 대화를 시작할 때마다 읽힙니다 — *"loaded at the start of every conversation"*
> - 길이 권고 — *"target under 200 lines per CLAUDE.md file"* (길수록 맥락을 더 쓰고 덜 지킨다는 설명이 이어집니다)
> - 지시가 구체적이고 짧을수록 더 꾸준히 지킨다고 안내합니다.
> - 규칙 파일을 나눌 때는 *"Each file should cover one topic"* — 한 파일에 한 주제.

### 무엇을 넣고, 무엇을 빼나

| 넣는다 (각 한두 줄) | 뺀다 |
|------|------|
| 나는 누구인가 — 사업 맥락 1~2줄 | AI가 파일을 열어 보면 알 수 있는 것(파일 목록 · 강의 가격표 등) |
| 말투 — 2~3줄 | 길고 가끔만 쓰는 양식 → 별도 파일로 |
| 결과 형식 — 순서 한 줄 | 「잘 해주세요」 같은 막연한 말 |
| 절대 하지 말 것 — 2~3줄 | 같은 뜻을 두 번 쓴 줄, 서로 부딪치는 줄 |

### 4단계: 짧은 CLAUDE.md 만들기

텍스트 에디터(메모장, VS Code 등)를 열고 `practice-data/creator/CLAUDE.md` 파일을 새로 만들어 아래 내용을 붙여 넣습니다. **스무 줄이 안 됩니다.** 이 정도면 충분합니다.

```text
# 지우의 업무 규칙서

## 나는 누구인가
1인 콘텐츠 사업자 지우. 온라인 강의 · 주간 뉴스레터 · 1:1 컨설팅을 혼자 운영한다.

## 말투
- 친근한 "~해요" 체
- 전문용어는 바로 뒤 괄호에 쉬운 풀이
- 비개발자가 읽는다고 생각하고 쓴다

## 결과 형식
분석은 항상 세 줄 요약 → 관찰 → 해석 → 제안 순서.

## 절대 하지 말 것
- 파일에 없는 수치를 지어내지 않는다. 확인 안 된 내용은 "추정"이라고 표시한다

```

> 💡 **강의 목록 · 파일 목록은 왜 뺐을까?** 강의 이름과 가격, 파일마다의 설명은 AI가 파일을 열어 보면 알 수 있는 내용입니다. 매 대화마다 읽힐 필요가 없으니 뺐습니다. 「지우면 AI가 실수할까?」 — 아니라면 빼는 게 맞습니다.

**기대 결과**: 터미널에서 아래를 실행해 파일이 생겼는지, 몇 줄인지 확인합니다.


파일 이름과 크기, 그리고 20줄 안팎의 줄 수가 보이면 성공입니다.

## 📂 실습 2 — 긴 규칙은 따로 빼기 (15분)

쓰다 보면 규칙이 길어지는 순간이 옵니다. 대표적인 게 **보고서 양식**입니다. 제목 · 날짜 · 항목별 길이 · 출처 표기 · 파일명까지 정하면 열 줄이 훌쩍 넘습니다. 그런데 보고서는 가끔만 만듭니다. 이걸 CLAUDE.md 에 다 넣으면, 보고서와 상관없는 대화에서도 매번 읽힙니다.

그래서 **따로 빼고, 규칙서에는 「언제 무엇을 읽어라」 한 줄만** 둡니다.

### 6단계: 보고서 규칙 파일 만들기 + 규칙서에 한 줄

CC 안에서 아래를 그대로 입력합니다.

```text
이 폴더에 rules 폴더를 만들고, rules/보고서-형식.md 파일에 아래 규칙을 적어줘.

# 보고서 형식
- 맨 위: 제목 한 줄 + 작성 날짜
- 1. 세 줄 요약 — 30초 안에 핵심을 잡을 수 있게
- 2. 관찰 — 파일에서 실제로 보이는 것, 수치는 직접 인용
- 3. 해석 — 왜 그렇게 됐을지 가설, "추정" 표시
- 4. 다음 달 할 일 3가지
- 맨 끝: 근거로 쓴 파일 이름 목록
- 파일로 저장할 때 이름은 "날짜-보고서-주제.md"

그리고 CLAUDE.md 맨 끝에 아래 한 줄만 추가해줘.
보고서를 만들 때는 rules/보고서-형식.md 를 먼저 읽고 따른다.
```

**기대 결과**:

```
rules/보고서-형식.md 파일을 만들고, CLAUDE.md 끝에 한 줄을 추가했어요.
```

CC가 파일을 만들거나 고쳐도 되는지 물으면, 바뀌는 내용이 「새 파일 1개 + 규칙서 한 줄」뿐인지 읽고 허락합니다.

**관찰/체크포인트**: 터미널을 하나 더 열거나 CC 를 잠시 나와서 확인해 보세요.

```bash
wc -l CLAUDE.md
cat rules/보고서-형식.md
```

규칙서는 여전히 스무 줄 남짓이고, 보고서 규칙은 별도 파일에 들어 있나요? ✓

> 💡 확인하려고 CC 를 이미 나왔다면, 다음 단계의 `/exit` 는 건너뛰고 `claude` 만 입력하면 됩니다.

### 7단계: 새 대화에서 보고서 요청 — 필요할 때 읽는지 보기

규칙서는 새 대화를 시작할 때 읽히므로, 다시 켭니다.

```text
/exit
```

```bash
claude
```

먼저 보고서와 **상관없는** 질문을 하나 합니다.

```text
newsletter_stats.csv 에서 오픈율이 가장 높은 호 하나만 알려주세요.
```

**기대 결과**: 짧은 답이 나옵니다. 보통은 `rules/보고서-형식.md` 를 열지 않고 바로 답합니다. 필요 없는 일이니까요. 혹시 열었다면 그것도 AI 의 판단이니 그대로 다음 질문으로 넘어가세요.

이제 보고서를 요청합니다.

```text
3월 뉴스레터 성과를 보고서로 정리해서 파일로 저장해 주세요.
```

**기대 결과**: 답을 만들기 전에 `rules/보고서-형식.md` 를 읽는 줄(예: `Read … 보고서-형식.md`)이 대개 지나가고, 제목 · 날짜 → 세 줄 요약 → 관찰 → 해석 → 다음 달 할 일 3가지 → 근거 파일 목록 순서의 보고서가 `날짜-보고서-주제.md` 이름으로 저장됩니다.

**관찰/체크포인트**:
- 보고서 요청에서 규칙 파일을 열었나요? ✓ (안 열었다면 「rules/보고서-형식.md 를 먼저 읽고 다시 써 주세요」라고 한 번 더 시키고, 규칙서 문장에 「언제」 읽는지가 분명한지 점검합니다)
- 보고서가 규칙 파일의 순서를 그대로 따랐나요? ✓
- 규칙서(CLAUDE.md)에는 보고서 양식이 한 줄도 없는데 지켜졌나요? ✓ — 경로 한 줄이 필요할 때 문을 열어 준 것입니다.

---

### 8단계: `@파일` 과 「경로 한 줄」은 다릅니다

CLAUDE.md 에 파일을 연결하는 방법은 두 가지입니다. 효과가 다르니 구분해서 씁니다.

| 쓰는 법 | 무슨 일이 일어나나 | 언제 쓰나 |
|---------|-------------------|-----------|
| `@rules/보고서-형식.md` | 그 파일을 규칙서에 **끼워 넣습니다.** CC 가 시작할 때 같이 읽혀서, 매 대화에 들어갑니다 | 늘 필요한 내용을 여러 파일로 정리해 둘 때 |
| `보고서를 만들 때는 rules/보고서-형식.md 를 먼저 읽고 따른다` | 경로만 알려 둡니다. **그 상황이 왔을 때** CC 가 파일을 열어 읽기를 기대하는 방법입니다(AI 의 판단이라 늘 보장되지는 않습니다) | 길고 가끔만 필요한 규칙 |

> 📎 공식 문서도 `@` 로 가져온 파일은 *시작할 때 CLAUDE.md 와 함께 읽힌다*고 설명합니다. 그래서 「필요할 때만」 읽히게 하려면 `@` 가 아니라 경로 문장을 씁니다.
>
> 참고로 `.claude/rules/` 폴더에 규칙 파일을 넣는 방법도 있습니다. 주제별로 파일을 나눠 정리하기 좋지만, 따로 조건을 달지 않으면 이 폴더의 파일도 매 대화마다 읽힙니다. 오늘 만든 `rules/` 폴더는 `.claude/rules/` 와 다른 폴더라서 자동으로 읽히지 않습니다. 공식 문서는 `.claude/rules/` 의 파일에 `paths` 조건을 달아, 그 경로의 파일을 다룰 때만 읽히게 하는 방법도 안내합니다.

**관찰/체크포인트**: 내 규칙 중 「늘 필요」한 것과 「가끔 필요」한 것을 하나씩 떠올려 보세요. 앞의 것은 규칙서에 짧게, 뒤의 것은 따로 빼고 경로 한 줄입니다.

## ✂️ 실습 3 — 키우고, 줄이기 (10분)

규칙서는 쓰면서 자랍니다. 다만 **자라는 만큼 줄이는 습관**이 같이 있어야 짧게 유지됩니다.

### 9단계: 일하면서 배운 것 더하기 — 어디에 넣을지 가르기

실습하다 새로 알게 된 두 가지를 규칙으로 남겨 봅니다. 하나는 짧고 늘 필요하고, 하나는 길고 가끔 필요합니다.

```text
아래 두 가지를 규칙으로 남겨줘.

1) CLAUDE.md 에 짧게 추가:
## 내가 부르는 강의 이름
- "챗GPT 강의" = "챗GPT로 콘텐츠 10배 빠르게"
- "클로드코드 강의" = "클로드코드로 업무 자동화 입문"

2) rules/강의-런칭.md 새 파일로:
사전등록 공지 뉴스레터(D-7) → 마감 임박 뉴스레터(D-1) → 정식 오픈·온보딩.
2026-03 클로드코드 강의에서 확인한 순서. 다음 강의 런칭 계획을 세울 때 기본값으로 쓴다.
그리고 CLAUDE.md 에 "강의 런칭 계획을 세울 때는 rules/강의-런칭.md 를 먼저 읽는다" 한 줄 추가.
```

**기대 결과**:

```
CLAUDE.md 에 「내가 부르는 강의 이름」 두 줄과 런칭 안내 한 줄을 더했고,
rules/강의-런칭.md 를 새로 만들었어요.
```

**관찰/체크포인트**: 별칭은 왜 규칙서에 넣었을까요? 내가 "챗GPT 강의"라고 부를 때마다 AI가 알아들어야 하니 **늘 필요**합니다. 지우면 AI가 실수합니다. 런칭 순서는 **가끔 필요**하니 따로 뺐습니다.

---

### 10단계: 줄이기 점검 — "이 줄을 지우면 AI가 실수할까?"

규칙서가 길어졌다 싶을 때 쓰는 점검입니다.

```text
CLAUDE.md 를 한 줄씩 보고, 지워도 네가 실수하지 않을 줄과
서로 부딪치거나 같은 뜻을 두 번 쓴 줄을 골라 줘.
지우지는 말고 목록과 이유만 보여 줘.
```

**기대 결과**: "이 줄은 파일을 열면 알 수 있어요", "이 두 줄은 같은 뜻이에요" 같은 후보 목록이 나옵니다.

**관찰/체크포인트**: 목록을 보고 지울지는 **내가** 정합니다. 지우기로 했다면 `/memory` 를 입력해 규칙서를 열고 직접 고치거나, CC 에 "그 줄들을 지워줘"라고 부탁합니다.

> 💡 **`/memory`** — CC 대화 중에 규칙서를 바로 열어 확인 · 편집하는 명령입니다. 한두 줄 고칠 때 편합니다.
> 💡 **`/init`** — 규칙서를 처음 만들기 막막할 때, CC 가 폴더를 살펴보고 초안을 써 줍니다. 초안은 길고 일반적일 수 있으니, 받은 뒤 10단계 점검으로 꼭 줄입니다.

### 다른 트랙이라면?

지우(creator) 외에 다른 트랙으로 이 강의를 듣고 있다면, CLAUDE.md의 사업 내용과 파일명만 내 업종에 맞게 바꾸면 **똑같은 실습 흐름**으로 진행할 수 있습니다.
- 🛒 **store**: 취급 상품 · 반품 정책은 규칙서에 짧게, 상세페이지 작성 양식은 `rules/` 로
- 💼 **freelancer**: 서비스 종류 · 응대 톤은 규칙서에, 청구서 형식은 `rules/` 로
- ☕ **local**: 가게 이름 · 영업시간은 규칙서에, SNS 안내문 양식은 `rules/` 로

틀은 같습니다. 늘 필요한 것은 짧게 규칙서에, 길고 가끔 필요한 것은 따로.

## 💡 핵심 규칙 정리

### 규칙 1: CLAUDE.md = "AI에게 주는 업무 매뉴얼"

매번 설명하는 대신, 한 번 적어두면 자동으로 읽힙니다.

```
❌ 매 대화마다: "저는 강의 제작자고, 친근하게, 수치 인용, 세 줄 요약…"
✅ CLAUDE.md에 한 번: 이후 모든 대화에서 자동 적용
```

### 규칙 2: 짧게 — 매번 통째로 읽힌다

```
한 파일 200줄 아래
줄마다: "이 줄을 지우면 AI가 실수할까?" → 아니면 지운다
AI가 파일을 열면 아는 것(목록 · 가격표)은 넣지 않는다
```

### 규칙 3: 나눠 두기 — 길고 가끔 필요한 규칙은 따로

```
CLAUDE.md          → 늘 필요한 것만 짧게
rules/주제.md      → 길고 가끔 필요한 것
CLAUDE.md 의 한 줄 → "○○할 때는 rules/주제.md 를 먼저 읽는다"
```

### 규칙 4: `@파일` = 끼워 넣기(매번) · 경로 한 줄 = 필요할 때

`@` 로 연결한 파일은 시작할 때 같이 읽힙니다. 「필요할 때만」 읽히게 하려면 경로 문장을 씁니다(8단계 표).

### 규칙 5: 자라지만, 입구는 짧게

오늘 만든 CLAUDE.md는 끝이 아니라 시작입니다. 다만 자랄수록 **입구는 짧게, 나머지는 나눠서** 유지합니다 — 강사의 실제 구성(입구 269자 → 필요할 때만 읽는 전문 20장)이 그 모습입니다.

```
cc-05 CLAUDE.md
    → codex-06 AGENTS.md (Codex용 규칙서 — 파일 이름만 다른 같은 원리)
    → Part 3 지식관리 규칙 (옵시디언 저장 방식)
    → Part 5~6 봇 성격 soul.md (AI 에이전트 팀의 뼈대)
```
